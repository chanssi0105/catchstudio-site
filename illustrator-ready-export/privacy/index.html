한국어

이 방침은 계정별 무료 체험 확인과 사용 통계를 사용하는 Illustrator Ready Export에 적용됩니다. 디자인 변환과 파일 생성은 사용자 기기의 플러그인 안에서 처리됩니다.

1. 무료 체험과 결제 확인

무료 체험은 피그마 계정 기준으로 최대 3회, 첫 실행 후 7일이며 둘 중 먼저 도달한 시점에 끝납니다. 서버가 횟수와 기간을 확인하므로 무료 내보내기에는 인터넷 연결이 필요합니다. 피그마가 결제 완료(PAID)로 확인한 사용자는 체험 확인 서버의 연결이나 응답 없이도 무제한 내보내기를 사용할 수 있습니다. 이는 피그마 자체의 온라인 기능과 별개입니다.

2. 서버로 보내고 확인하는 정보

  • 피그마 결제 확인 토큰: 피그마 API에서 이 플러그인의 사용자 ID와 결제 상태를 확인하는 데 사용합니다. 비밀번호나 카드 정보는 받지 않습니다.
  • 무료 사용 횟수, 요청한 내보내기 개수, 형식 이름(SVG·PDF·AI·IDML·PSD 등), 플러그인 버전, 언어(한국어 또는 영어).
  • 피그마가 제공한 첫 실행 후 경과 시간: 신규 계정의 체험 시작을 확인하는 데 사용하며 기존 체험을 연장하지 않습니다.
  • 플러그인 열기, 내보내기 성공·실패, 결제 안내 표시, 결제 버튼 클릭, 결제 완료 같은 이벤트 종류와 서버가 기록한 시각.

디자인 내용, 피그마 파일이나 내보낸 파일, 사용자 이름·파일 이름·레이어 이름, 이미지와 텍스트 내용은 서버로 전송하지 않습니다. 결제 사용자의 통계 요청도 전송될 수 있지만, 이 요청의 실패는 내보내기를 막지 않습니다.

3. 저장 목적과 보관 기간

계정 기록에는 피그마 사용자 ID, 무료 사용 횟수, 체험 시작·최근 확인 시각, 결제 상태와 플러그인 버전을 저장합니다. 무료 체험과 구매 상태 확인을 위해 사용하며 삭제 요청이 있을 때까지 보관합니다. 결제 확인 토큰 원문은 계정 기록이나 통계에 저장하지 않습니다.

사용 통계에는 사용자 ID의 HMAC-SHA256 해시만 저장하며 원본 사용자 ID와 토큰은 저장하지 않습니다. 이벤트 종류, 형식, 개수, 버전, 언어와 시각은 기능 사용·오류·무료에서 유료로의 전환을 파악하는 데 사용합니다. 통계의 보관 기간은 400일이며 만료 후 DynamoDB의 자동 삭제가 처리됩니다. 자동 삭제에는 처리 지연이 있을 수 있습니다. 해시로도 같은 사용자의 이벤트를 연결할 수 있으므로 완전히 식별 불가능한 정보라고 보지는 않습니다.

4. 처리 위치와 외부 서비스

체험 확인 서버와 데이터베이스는 AWS 서울 리전(ap-northeast-2)에서 처리·보관합니다. 결제 토큰은 결제 검증을 위해 피그마 API에 전달됩니다. 피그마의 계정·결제 처리에는 피그마의 정책이 별도로 적용됩니다. 이 방침은 플러그인의 데이터 처리에 관한 것이며 catch-studio.com 사이트 자체의 모든 데이터 처리를 설명하는 방침은 아닙니다.

5. 열람·삭제 요청과 문의

계정 기록과 관련 통계의 열람·삭제 요청은 catchstudio25@gmail.com으로 보내 주세요. 대상 피그마 계정을 확인하는 데 필요한 최소한의 정보를 요청할 수 있습니다. 결제 토큰, 비밀번호, 디자인 파일은 보내지 마세요. 문의를 위해 자발적으로 보내는 이메일과 내용은 요청 처리에 사용합니다.

6. 방침 변경

데이터 처리 방식이 바뀌면 이 페이지의 내용과 최종 수정일을 갱신합니다. 플러그인을 사용하기 전에 최신 내용을 확인할 수 있습니다.

English

This policy applies to Illustrator Ready Export with account-based trial verification and usage statistics. Design conversion and file generation happen inside the plugin on your device.

1. Free trial and purchase verification

The free trial allows up to 3 exports within 7 days of the first run, per Figma account, whichever limit is reached first. A server checks usage and time, so free exports need an internet connection. Users whose Figma payment status is PAID can export without limits even when the trial server is unavailable. This does not change the connectivity requirements of Figma itself.

2. Information sent and verified

  • A Figma plugin payment token, used with the Figma API to verify the user ID and purchase status for this plugin. We do not receive passwords or card details.
  • Free usage count, requested export count, format name (such as SVG, PDF, AI, IDML or PSD), plugin version and language (Korean or English).
  • Elapsed time since the first run, provided by Figma, to establish a new account's trial start. It cannot extend an existing trial.
  • Event types such as plugin open, export success or failure, paywall display, checkout click and purchase detection, with server-generated timestamps.

We do not send design content, Figma files or exported files, user names, file names, layer names, images or text content to the server. Paid users may also send statistics requests, but a failed request never blocks their exports.

3. Purpose and retention

Account records store the Figma user ID, free usage count, trial start and last verification timestamps, payment status and plugin version. They are used for trial and purchase verification and retained until a deletion request. Raw payment tokens are not stored in account records or statistics.

Statistics store only an HMAC-SHA256 hash of the user ID, not the original ID or token. Event type, format, count, version, language and timestamp help us understand feature use, failures and trial-to-paid conversion. Statistics are retained for 400 days and then expire for automatic DynamoDB deletion, which may take additional processing time. A hash can link events from the same user, so we do not describe this data as completely unidentifiable.

4. Processing location and external services

The trial server and databases process and store data in AWS's Seoul region (ap-northeast-2). Payment tokens are forwarded to the Figma API for verification. Figma's own policies separately govern its account and payment processing. This policy describes the plugin's data processing, rather than all processing by the catch-studio.com website.

5. Access, deletion and contact

To request access to or deletion of account records and related statistics, email catchstudio25@gmail.com. We may request the minimum information needed to verify the relevant Figma account. Do not send payment tokens, passwords or design files. Email addresses and content voluntarily sent for support are used to handle your request.

6. Changes

When data processing changes, we update this page and its revision date. You can review the latest policy before using the plugin.
