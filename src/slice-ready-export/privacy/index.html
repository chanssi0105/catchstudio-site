Slice Ready Export

Privacy Policy

Version 1.0 · Updated October 7, 2026

1. Operator and purpose

catchstudio operates Slice Ready Export. We verify Figma purchases, enforce the account-based free trial, prevent duplicate charges, restore credits when a download cannot start, and understand usage and failures. We do not use this data for advertising or sell it.

2. What is sent and verified

The plugin sends a Figma plugin payment-verification token, plugin version and language. Trial requests include the elapsed seconds since the first run; consumption requests include the number of frames, an operation identifier and, when needed, a cancellation flag. The API also accepts a local free-use count and a format name for trial requests; the current plugin does not send these two optional fields there.

Usage events contain an event type (open, export success/failure, paywall shown, checkout click or paid), language, version and, when available, format (JPG, PNG-24 or PNG-8), number of slices, number of frames and save mode (ZIP or individual). The server adds timestamps and generated event identifiers.

Our backend sends the payment token to Figma's Payments API. It verifies the Figma user ID, plugin resource ID/type and purchase status. Other response content is not stored as an account or usage record.

3. What stays on your device

Designs, images, text content, Figma files, exported files, frame/layer names, file names and email addresses are not sent to our backend by the plugin. Rendering, image optimization and ZIP creation run on your device. We collect no passwords or card details. Email addresses and messages you voluntarily send for support are used to handle that request.

Figma clientStorage on your device stores recent/favorite/custom presets and the save preference. A pending recovery marker contains the operation ID, frame count, window identifier and creation time; it contains no payment token or design. Figma's own data handling is governed by its policy.

4. Records and retention

  • Account records: the Figma user ID, free-use count, trial start, last verification time, paid flag and plugin version. These records have no automatic expiry; we keep them to enforce the account trial until a verified deletion request.
  • Usage statistics: an HMAC-SHA256 user ID hash, event type, format/count/frame count/save mode where available, version, language, date/time, generated event identifier and expiry. The hash can link one user's events; it is not completely anonymous.
  • Consumption receipts: a SHA256-derived account key, operation ID, frame count, allowed/cancelled flags and expiry. These are separate from statistics and support idempotency and credit recovery.
  • Statistics and consumption receipts expire 400 days after creation. DynamoDB TTL deletes expired records asynchronously, so physical deletion may take additional days.
  • Payment tokens are used transiently in plugin/server memory, not persisted in databases or application logs. The server may cache a verified token digest and the associated account/payment result for up to 60 seconds.
  • Operational logs contain request paths/status codes, initialization/request-stage timing, and recognized response field names; no token, raw account ID or response body is intentionally logged. The configured log retention is 14 days. Service-generated invocation identifiers and time/resource metadata may also appear.
  • Account-table point-in-time recovery backups may retain earlier records for up to 35 days after deletion. Deletion from live records does not immediately remove prior backup copies.

5. Providers, location and safeguards

AWS processes backend/database/log data in Seoul, Republic of Korea (ap-northeast-2). Figma processes payment verification under Figma's Privacy Policy. These providers receive the information needed for those functions; we do not provide data to advertisers.

Plugin-to-backend and backend-to-Figma requests use HTTPS. The plugin network allowlist contains only our trial API. Server credentials are held in encrypted AWS storage and service permissions are limited. We claim no independent security certification for this plugin.

6. Your requests and security reports

Contact the privacy representative, catchstudio representative: catchstudio25@gmail.com / 0507-2097-3010. You may request access, correction or deletion. We may ask for minimum information needed to verify your Figma account, then handle the request without undue delay. Deleting trial records does not promise a new trial.

Send security reports to the same email. Do not send payment tokens, passwords, card details or design files. We do not currently publish a dedicated vulnerability-management process. Support correspondence is kept while the request is handled; deletion can be requested through the same contact.

7. Updates and reference

Material changes will be reflected on this page with a revised date and communicated through the plugin's release information where appropriate.

개인정보 처리방침

버전 1.0 · 변경일 2026년 10월 7일

1. 운영자와 처리 목적

catchstudio는 Slice Ready Export를 운영합니다. 피그마 구매 확인, 계정별 무료 체험 관리, 중복 차감 방지, 다운로드를 시작하지 못한 경우의 사용 횟수 복구, 이용 현황과 오류 파악을 위해 정보를 처리합니다. 광고에 이용하거나 판매하지 않습니다.

2. 전송·확인하는 정보

플러그인은 피그마 플러그인 결제 확인 토큰, 버전, 언어를 보냅니다. 체험 확인에는 첫 실행 후 경과 초, 차감 요청에는 프레임 수, 요청 식별값과 필요한 경우 취소 여부가 포함됩니다. API는 체험 요청의 로컬 무료 사용 횟수와 형식 이름도 받을 수 있지만, 현재 플러그인은 이 두 선택 항목을 해당 요청에 보내지 않습니다.

통계 요청에는 이벤트 종류(실행, 내보내기 성공·실패, 결제 안내 표시, 구매 버튼 클릭, 결제 완료), 언어, 버전과 해당되는 경우 형식(JPG·PNG-24·PNG-8), 조각 수, 프레임 수, 저장 방식(ZIP·낱개)이 들어갑니다. 서버는 시각과 통계 기록 식별값을 추가합니다.

서버는 결제 확인 토큰을 피그마 Payments API로 보내 계정 식별값(user_id), 플러그인 식별값·종류, 결제 상태를 확인합니다. 응답의 다른 내용 전체를 계정·통계 기록으로 저장하지 않습니다.

3. 기기에 남는 정보

디자인·이미지·텍스트 내용·피그마 파일·내보낸 파일·프레임 및 레이어 이름·파일 이름·이메일은 플러그인이 당사 서버에 보내지 않습니다. 렌더링·이미지 최적화·ZIP 생성은 사용자 기기에서 처리합니다. 비밀번호와 카드 정보도 수집하지 않습니다. 문의 이메일로 사용자가 직접 보내는 주소와 메시지는 해당 문의 처리에 사용합니다.

기기의 피그마 clientStorage에는 최근 사용·즐겨찾기·내 프리셋과 저장 방식이 보관됩니다. 실패 복구 대기 기록에는 요청 식별값·프레임 수·실행 창 식별값·생성 시각이 있으며 결제 토큰이나 디자인은 없습니다. 피그마 자체 처리는 피그마 정책을 따릅니다.

4. 저장 항목과 보관 기간

  • 계정 기록: 피그마 user_id, 무료 사용 횟수, 체험 시작·마지막 확인 시각, 결제 여부, 플러그인 버전. 자동 만료가 없으며 계정별 체험 관리에 사용하고 본인 확인 후 삭제 요청을 처리합니다.
  • 이용 통계: HMAC-SHA256 계정 해시, 이벤트 종류, 해당되는 형식·조각 수·프레임 수·저장 방식, 버전, 언어, 날짜·시각, 통계 식별값, 만료 시각. 해시는 같은 계정의 기록을 연결할 수 있어 완전한 익명 정보로 표현하지 않습니다.
  • 차감 요청 기록: SHA256 계정 해시 기반 키, 요청 식별값, 프레임 수, 허용·취소 여부, 만료 시각. 통계와 별개로 중복 차감 방지와 사용 횟수 복구에 사용합니다.
  • 통계·차감 요청 기록은 생성 400일 후 만료됩니다. DynamoDB TTL의 자동 삭제는 비동기 처리이므로 실제 삭제까지 추가로 며칠 걸릴 수 있습니다.
  • 결제 토큰은 플러그인·서버 메모리에서 일시적으로 사용하며 데이터베이스와 애플리케이션 로그에 저장하지 않습니다. 서버는 확인된 토큰의 해시와 연결된 계정·결제 결과를 최대 60초 캐시할 수 있습니다.
  • 운영 로그에는 경로·상태 코드, 초기화·요청 단계별 시간, 알려진 응답 필드 이름만 기록하고 토큰·원문 계정 ID·응답 본문을 의도적으로 기록하지 않습니다. 설정된 보관 기간은 14일입니다. 서비스가 생성하는 호출 식별값·시간·리소스 메타데이터도 포함될 수 있습니다.
  • 계정 테이블의 시점 복구 백업에는 삭제 전 기록이 최대 35일 남을 수 있습니다. 운영 기록 삭제가 이전 백업의 즉시 삭제를 뜻하지 않습니다.

5. 처리업체·위치·보호조치

AWS는 대한민국 서울 리전(ap-northeast-2)에서 서버·데이터베이스·로그를 처리합니다. 피그마의 결제 확인에는 피그마 개인정보 정책이 적용됩니다. 각 업체에는 해당 기능에 필요한 정보가 전달되며 광고업체에 제공하지 않습니다.

플러그인과 서버, 서버와 피그마 사이에는 HTTPS를 사용합니다. 플러그인 네트워크 허용 목록에는 체험 API만 있습니다. 서버 자격 정보는 암호화된 AWS 저장소에 보관하고 권한을 서비스 운영 범위로 제한합니다. 이 플러그인의 독립 보안 인증을 주장하지 않습니다.
